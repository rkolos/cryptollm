# Техническое Задание (ТЗ): 10.6 Создание "Промпт-Реестра" и Тестовых Кейсов

**Эпик:** 10. 🧠 Архитектура Промптов и "Личность" Трейдера **Задача:** 10.6 🧪 Создание "Промпт-Реестра" и Тестовых Кейсов **Архитектор:** Gemini **Дата:** 29.10.2025

## 1\. Цель Задачи

Завершить Эпик 10, структурировав все созданные `.md` файлы промптов в единый версионированный "реестр" (папку `v1`). Создать документ `prompt_test_cases.md`, содержащий "юнит-тесты" (примеры входных данных и ожидаемых JSON-ответов) для ручной валидации и регрессионного тестирования промптов.

## 2\. Зависимости Задачи

- **`system.md` (10.1, 10.3):** (Артефакт) Файл "конституции" LLM.
- **`user_template.md` (10.4):** (Артефакт) Файл "шаблона задачи".
- **`output_schema.md` (10.5):** (Артефакт) Файл "контракта" ответа.
- **`LLMRequestAssemblerService` (4.6):** (Потребитель) Должен быть обновлен, чтобы читать файлы из `src/prompts/v1/`.

## 3\. Описание и Нюансы Реализации

### 3.1. Создание Структуры Папок "Промпт-Реестра"

Разработчик должен создать следующую структуру папок в `/src`:

    /src
      /prompts
        /v1
          (здесь будут лежать все .md файлы)

### 3.2. Перемещение Артефактов Эпика 10

Все `.md` файлы, созданные в этом эпике, должны быть размещены внутри `src/prompts/v1/`:

- `src/prompts/v1/system.md` (из 10.1, 10.3)
- `src/prompts/v1/user_template.md` (из 10.4)
- `src/prompts/v1/output_schema.md` (из 10.5)

### 3.3. Создание Файла Тестовых Кейсов

Разработчик (Prompt Engineer) должен создать новый файл:

- `src/prompts/v1/prompt_test_cases.md`

### 3.4. Содержание `prompt_test_cases.md`

Этот файл будет содержать набор сценариев для ручного тестирования промптов (например, в "песочнице" OpenAI или Anthropic). Каждый тест-кейс должен включать:

1.  **Сценарий:** Описание ситуации.
2.  **Пример JSON-входа (Ключевые части):** Упрощенный JSON, имитирующий то, что сгенерирует `LLMRequestAssemblerService`.
3.  **Ожидаемый `justification` (Логика):** Какую "цепочку размышлений" мы ожидаем.
4.  **Ожидаемый `decisions` (Действие):** Какой JSON-приказ мы ожидаем.

**Содержание (Пример):**

> # Тест-Кейсы для Промптов V1
>
> ## Тест-кейс 1: "Контр-тренд на перепроданности" (Long)
>
> - **Сценарий:** Рынок в панике, BTC сильно упал и достиг ключевого уровня поддержки. RSI показывает глубокую перепроданность.
> - **Пример JSON-входа (Ключевые части):**
>
>       "strategy_context": {
>         "risk_rules": { "default_risk_per_trade_percent": 1.5, ... },
>         "macro_context": { "fear_and_greed_text": "Extreme Fear", "fear_and_greed_index": 25 }
>       },
>       "technical_analysis": {
>         "analysis_4h": {
>           "rsi": 25.5,
>           "key_levels": { "low": 29800 }
>         }
>       },
>       "market_data": { "current_price": 29850 },
>       "account_state": { "available_quote_balance": 10000, "open_positions": [] }
>
> - **Ожидаемый `justification` (Логика):** "Рынок в 'Extreme Fear' (25), RSI на 4H перепродан (25.5) и цена находится у `key_levels.low` (29800). Это сильный сигнал к покупке на отскок. Так как портфель пуст, я вхожу со стандартным риском 1.5%." (Или _уменьшенным_ риском из-за "Extreme Fear", если так настроена V1).
> - **Ожидаемый `decisions` (Действие):**
>
>       "decisions": [
>         {
>           "action": "OPEN_LONG",
>           "pair": "BTC/USDT",
>           "parameters": {
>             "type": "limit",
>             "price": 29900.0,
>             "risk_percent": 1.5,
>             "stop_loss_price": 29450.0,
>             "take_profit_price": 31000.0
>           }
>         }
>       ]
>
> ## Тест-кейс 2: "Флэт / Нет тренда" (Hold)
>
> - **Сценарий:** Рынок "скучный", цена в середине диапазона, ADX (доп. индикатор) показывает отсутствие тренда.
> - **Пример JSON-входа (Ключевые части):**
>
>       "strategy_context": {
>         "macro_context": { "fear_and_greed_text": "Neutral", "fear_and_greed_index": 50 }
>       },
>       "technical_analysis": {
>         "analysis_1h": {
>           "rsi": 52.0,
>           "bollinger": { "upper": 30500, "middle": 30000, "lower": 29500 },
>           "ADX_1h": 19.5
>         }
>       },
>       "market_data": { "current_price": 30100 },
>       "account_state": { "open_positions": [] }
>
> - **Ожидаемый `justification` (Логика):** "Нет четкого сигнала. ADX на 1H ниже 20 (19.5), что указывает на отсутствие тренда. Цена находится в середине канала Боллинджера. В рынок не лезу, жду прояснения ситуации."
> - **Ожидаемый `decisions` (Действие):**
>
>       "decisions": []
>
> ## Тест-кейс 3: "Превышение Лимита Риска" (Risk Limit / Hold)
>
> - **Сценарий:** Появляется идеальный сигнал `OPEN_LONG`, _но_ наш портфель уже загружен риском почти "под завязку".
> - **Пример JSON-входа (Ключевые части):**
>
>       "strategy_context": {
>         "risk_rules": {
>           "default_risk_per_trade_percent": 1.5,
>           "max_total_portfolio_risk_percent": 10.0
>         }
>       },
>       "technical_analysis": { ... /* (Идеальный сигнал LONG) */ ... },
>       "account_state": {
>         "total_portfolio_value_usdt": 50000,
>         "open_positions": [
>           { "pair": "ETH/USDT", "side": "long", "amount": 10, "average_entry_price": 1800, "stop_loss_price": 1750 } /* (Риск: (1800-1750)*10 = $500) */
>         ],
>         "calculated_total_portfolio_risk_percent": 9.5
>         /* (Примечание: это поле должно быть добавлено в `account_state` (Задача 4.5)) */
>       }
>
> - **Ожидаемый `justification` (Логика):** "Вижу сильный сигнал LONG по BTC/USDT, но не могу войти. Текущий риск портфеля 9.5%. Добавление новой сделки с риском 1.5% (или $750) превысит `max_total_portfolio_risk_percent` (10%). Сохраняю позицию (HOLD), чтобы не нарушать правила управления капиталом."
> - **Ожидаемый `decisions` (Действие):**
>
>       "decisions": []
