# Промпты V1

## Архитектурное Решение: Упрощение Загрузки Профиля Стратегии

В первой итерации проекта (V1) стратегия торговли **не модульная** и **зашита** непосредственно в `system.md`.

### Реализация

1. **Системный промпт (`system.md`)**:
   - Содержит единую стратегию V1 (консервативный свинг-трейдинг)
   - Определяет роль, стиль торговли и ключевые индикаторы
   - Не зависит от внешних файлов стратегий

2. **ConfigService**:
   - Предоставляет `risk_rules` через `getRiskRules()`
   - Предоставляет базовую информацию о стратегии через `getStrategyContext()` (role, style)
   - **НЕ реализует** логику переключения стратегий

3. **LLMRequestAssemblerService** (будет реализован в задаче 4.6):
   - Загружает `system.md` как системный промпт
   - Собирает JSON-запрос, включая `risk_rules` из `ConfigService`
   - **НЕ реализует** логику загрузки отдельных файлов стратегий

### Зачем это сделано

Это упрощение для первой итерации позволяет:
- Быстрее начать работу с одной проверенной стратегией
- Избежать сложности модульной системы стратегий
- Сосредоточиться на отладке основного функционала

В будущих версиях можно реализовать модульную систему стратегий, но для V1 стратегия фиксирована в `system.md`.
