# Техническое Задание (ТЗ): 4.1 Движок Технического Анализа (TAEngineService)

**Эпик:** 4. 📊 "Наблюдатель" (Watcher) - Сбор Данных и Технический Анализ **Задача:** 4.1 Движок Технического Анализа **Архитектор:** Gemini **Дата:** 29.10.2025

## 1\. Цель Задачи

Создать **Singleton-сервис** `TAEngineService`, который инкапсулирует всю логику расчетов Технического Анализа (ТА), используя библиотеку `technicalindicators`.

Сервис должен предоставлять единый, отказоустойчивый метод `getAnalysis`, который принимает "сырые" данные OHLCV и список _дополнительно_ запрашиваемых индикаторов, а возвращает строго типизированный объект с результатами ТА (согласно Приложениям А и Б в `about.md`).

## 2\. Архитектурное Решение

1.  **Финансовая Точность (Критично):** `TAEngineService` — это "хранитель" точности. Все входные данные (`OHLCV`) и все выходные данные (`AnalysisResult`) _обязаны_ использовать тип `Decimal` (из `decimal.js`).
2.  **Трансляция Типов (Обязательно):** Библиотеки ТА (e.g., `technicalindicators`) работают с нативным типом `number[]`. Сервис _обязан_ выполнять: **`Decimal[]` → `number[]`** (перед расчетом) и **`number` → `Decimal`** (сразу после расчета). **Ни один нативный `number` не должен покидать этот сервис.**
3.  **Двухпакетный Расчет:** Метод `getAnalysis` _всегда_ должен рассчитывать "Базовый Пакет" (EMA 50/200, RSI, MACD, BB, KeyLevels). "Расширенный Пакет" (ADX, ATR, и т.д.) должен рассчитываться _только_ по запросу (если он указан в аргументе `requestedData`).
4.  **Отказоустойчивость:** В случае ошибки расчета (например, недостаточно свечей для EMA 200), соответствующее поле _должно_ быть установлено в `null`, а не вызывать сбой всего приложения.

## 3\. Зависимости Задачи

- **Пакеты (1.2):** `technicalindicators`, `decimal.js`.
- **`LoggingService` (1.4):** Для логирования ошибок расчета.
- **Интерфейсы:** Необходимо создать/дополнить типы `OHLCV`, `AnalysisResult` и вспомогательные типы (например, `MACDResult`, `BollingerBandsResult`). Все числовые поля _обязаны_ использовать `Decimal`.

## 4\. Описание и Нюансы Реализации

### 4.1. Метод `getAnalysis(ohlcv: OHLCV[], requestedData: string[])`

1.  **Входная Трансляция (`_prepareTAInput`):**
    - **Логика:** Первым шагом _обязано_ быть преобразование входного массива `OHLCV[]` в объект с массивами `number[]` (для `open`, `high`, `low`, `close`, `volume`).
    - **Нюанс:** Использовать приватный метод `toNumber(decimalValue)`, который вызывает `decimalValue.toNumber()` для преобразования `DecimalValue` в `number`. Если `decimalValue` равен `null`, возвращать `0`.

2.  **Расчет "Базового Пакета" (`_calculateBasicPackage`):**
    - **Логика:** Выполнить расчет всех индикаторов из Приложения А (EMA 50, EMA 200, RSI 14, MACD, Bollinger Bands, KeyLevels).
    - **Нюанс отказоустойчивости:** Каждый индикатор _обязан_ быть обернут в отдельный `try/catch` блок. При ошибке расчета соответствующее поле устанавливается в `null`, и ошибка логируется как `warn`, но не прерывает расчет остальных индикаторов.
    - **Нюанс `KeyLevels`:** Расчет `high (N candles)` и `low (N candles)` _обязан_ выполняться через приватный метод `_calculateKeyLevels(ohlcv, period)` на оригинальных `OHLCV` (Decimal) данных, используя `Decimal.max()` и `Decimal.min()` для сохранения точности. Метод принимает период (по умолчанию 100 свечей) и возвращает `KeyLevels` с полями `period`, `high`, `low`.
    - **Нюанс EMA/RSI/MACD/BB:** Полученные результаты (которые будут `number[]` или объекты с `number`) _обязаны_ быть преобразованы в `Decimal` через приватный метод `toDecimal(value)` перед сохранением. Метод `toDecimal` обрабатывает `null`, `undefined`, `NaN`, `!isFinite` и возвращает `null` в этих случаях.
    - **Нюанс MACD:** Результат MACD содержит объект с полями `MACD`, `signal`, `histogram`, которые преобразуются отдельно.
    - **Нюанс Bollinger Bands:** Результат содержит объект с полями `upper`, `middle`, `lower`, которые преобразуются отдельно.

3.  **Расчет "Расширенного Пакета" (`_calculateExtendedPackage`):**
    - **Логика:** Выполнить расчет индикаторов из Приложения Б (ADX, ATR, OBV, VWAP, Stochastic) **только** при совпадении имени индикатора с элементом в `requestedData` (e.g., если запрошен `'ADX'`).
    - **Нюанс реализации:** Использовать `if (requestedData.includes('ADX')) { ... }` для условного расчета. Если индикатор не запрошен, соответствующее поле устанавливается в `null`.
    - **Нюанс отказоустойчивости:** Каждый индикатор _обязан_ быть обернут в отдельный `try/catch` блок. При ошибке расчета соответствующее поле устанавливается в `null`, и ошибка логируется как `warn`.
    - **Нюанс Stochastic:** Результат содержит объект с полями `k` и `d`, которые преобразуются отдельно.

4.  **Выходная Трансляция и Отказоустойчивость:**
    - **Логика:** Все возвращаемые поля в `AnalysisResult` _обязаны_ быть объединены из `basicPackage` и `extendedPackage` с использованием оператора `??` для установки `null` по умолчанию.
    - **Нюанс реализации:** В случае сбоя или недостатка данных (e.g., `ema50Result.length === 0`), соответствующее поле в `AnalysisResult` _обязано_ быть `null` или объектом с полями `null` внутри вспомогательного типа (например, `macd: { macd: null, signal: null, histogram: null }`).
    - **Нюанс пустого массива:** Если входной массив `ohlcv` пуст или равен `null`, метод _обязан_ вернуть результат через приватный метод `_getNullResult()`, который возвращает `AnalysisResult` со всеми полями `null`.
    - **Нюанс фатальной ошибки:** Весь метод `getAnalysis` _обязан_ быть обернут в `try/catch`. При фатальной ошибке (не связанной с отдельными индикаторами) метод логирует `error` и возвращает `_getNullResult()`. Общий `getAnalysis` _не должен_ бросать ошибку, а должен возвращать объект с `null` (т.е. быть отказоустойчивым).

## 5\. Критерии Приемки (Acceptance Criteria)

1.  Service & Types

    `TAEngineService` создан как Singleton. Интерфейс `AnalysisResult` создан, и _все_ его числовые поля (EMA, RSI, ATR, VWAP и т.д.) имеют тип `Decimal | null`.

2.  Precision(Критично)

    Метод `_prepareTAInput` корректно преобразует `Decimal` в `number` для библиотек.

3.  Precision(Критично)

    Методы расчета _корректно_ преобразуют финальный результат `number` обратно в `Decimal` (или `Decimal | null`).

4.  Logic:Basic

    Сервис _обязан_ всегда рассчитывать и возвращать полный "Базовый Пакет" (EMA 50/200, RSI, MACD, BB, KeyLevels).

5.  Logic:Extended

    Сервис _обязан_ рассчитывать индикаторы "Расширенного Пакета" (ADX, ATR, OBV, VWAP, Stochastic) _только_ при явном запросе через массив `requestedData`.

6.  KeyLevels

    Расчет `KeyLevels` _обязан_ использовать `Decimal.max/min` на исходных `OHLCV` для обеспечения точности, а не результаты TA-библиотек.

7.  Robustness

    В случае любого сбоя внутри `getAnalysis`, функция _обязана_ залогировать ошибку и вернуть `AnalysisResult` со всеми полями `null` через метод `_getNullResult()`, не вызывая сбой приложения. Каждый индикатор обрабатывается независимо с собственным `try/catch`.

8.  NullHandling

    Метод `toDecimal` корректно обрабатывает `null`, `undefined`, `NaN`, `!isFinite` и возвращает `null` в этих случаях.

9.  EmptyInput

    Если входной массив `ohlcv` пуст или равен `null`, метод возвращает `_getNullResult()` без попытки расчетов.
