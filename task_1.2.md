**Эпик:** 1. 🏗️ Ядро Проекта, Окружение и TypeScript (Core Project & Environment) **Задача:** 1.2 Установка и типизация зависимостей **Архитектор:** Gemini **Дата:** 29.10.2025

## 1\. Цель Задачи

Установить все основные runtime-библиотеки, необходимые для работы приложения, а также соответствующие пакеты типизации (`@types`) для обеспечения строгого контроля типов TypeScript.

## 2\. Описание и Нюансы Реализации

Разработчик должен разделить установку на `dependencies` (необходимые для запуска в production) и `devDependencies` (необходимые только для разработки, в данном случае — типизация).

### 2.1. Runtime Зависимости (Dependencies)

Выполнить установку следующих пакетов (командой `npm install <...>`):

- **`ccxt`**: Основная библиотека для взаимодействия с API бирж (Binance).
- **`pg`**: Клиент `node-postgres` для работы с базой данных PostgreSQL.
- **`decimal.js`**: **Критически важная** библиотека для всех финансовых расчетов (цены, объемы, PnL). Использование нативных `Number` для денег **запрещено** архитектурой (согласно `about.md`).
- **`winston`**: Библиотека для логирования (будет использована в Задаче 1.4).
- **`technicalindicators`**: Библиотека для расчетов технического анализа, написанная на чистом JS (будет использована в Задаче 4.1).
- **`tulind`**: Высокопроизводительная библиотека-обертка над C-библиотекой `ta-lib` для расчетов технического анализа (будет использована в Задаче 4.1).

### 2.2. Development Зависимости (DevDependencies)

Выполнить установку следующих пакетов (командой `npm install -D <...>`):

- **`@types/pg`**: Пакет деклараций типов для `node-postgres`.
- **`@types/tulind`**: Пакет деклараций типов для `tulind`.

**Архитектурное примечание:** Библиотеки `ccxt`, `decimal.js`, `winston` и `technicalindicators` поставляются со своими собственными `.d.ts` файлами, поэтому установка `@types` для них не требуется.

### 2.3. Критический Нюанс: Установка `tulind`

Библиотека `tulind` является JS-оберткой над C-библиотекой `ta-lib`. Для ее успешной установки (`npm install tulind`) и компиляции (через `node-gyp`) необходимо, чтобы **C-библиотека `ta-lib` была предварительно установлена в операционной системе**.

Разработчик должен убедиться, что `ta-lib` установлена в его окружении **до** запуска `npm install`.

- **Для macOS (через Homebrew):** `brew install ta-lib`
- **Для Ubuntu/Debian:** `apt-get install ta-lib-dev`
- **Для Windows:** Потребуется загрузка pre-built бинарных файлов `ta-lib` и указание путей к ним при установке.

## 3\. Критерии Приемки (Acceptance Criteria)

Задача считается выполненной, если:

1.  **\[package.json\]** Файл `package.json` обновлен:
    - Секция `dependencies` содержит `ccxt`, `pg`, `decimal.js`, `winston`, `technicalindicators`, `tulind`.
    - Секция `devDependencies` содержит `@types/pg`, `@types/tulind`.

2.  **\[Установка\]** Команда `npm install` завершается успешно без ошибок компиляции (особенно для `tulind`).
3.  **\[Компиляция\]** Команда `npm run build` (настроенная в Задаче 1.1) по-прежнему завершается успешно.
4.  **\[Проверка Типов\]** `tsc` (запускаемый через `npm run build`) **не** выдает ошибок типизации. Для проверки разработчик должен временно создать файл `src/temp-import-check.ts` (и удалить его после проверки) со следующим содержимым:

        // Этот файл только для проверки типов, он будет удален
        import { binance } from 'ccxt';
        import { Pool } from 'pg';
        import { Decimal } from 'decimal.js';
        import { createLogger } from 'winston';
        import { RSI } from 'technicalindicators';
        import { indicators } from 'tulind';

        // Проверка, что типы "подхватились"
        const v1: Pool = new Pool();
        const v2: Decimal = new Decimal(0);
        const v3 = createLogger();
        const v4 = RSI.calculate;
        const v5 = indicators.rsi;

    Запуск `npm run build` с этим файлом не должен вызывать ошибок TypeScript.
