# Техническое Задание (ТЗ): 10.4 Создание Шаблона "Задачи" (User Prompt Template)

**Эпик:** 10. 🧠 Архитектура Промптов и "Личность" Трейдера **Задача:** 10.4 ✍️ Создание Шаблона "Задачи" (User Prompt Template) **Архитектор:** Gemini **Дата:** 29.10.2025

## 1\. Цель Задачи

Создать файл `user_prompt_template.md`, который служит "телом" запроса к LLM. Этот шаблон будет содержать плейсхолдеры (`{{...}}`) для всех динамически предоставляемых данных (рынок, ТА, портфель) и финальной "задачи" (вопроса).

Этот шаблон будет загружаться `LLMRequestAssemblerService` (Задача 4.6), который заменит плейсхолдеры на реальные JSON-строки перед отправкой в `ProductionLLMService`.

## 2\. Зависимости Задачи

- **`LLMRequestAssemblerService` (4.6):** (Потребитель) Сервис, который будет читать этот `.md` файл и заполнять его.
- **`output_schema.md` (10.5):** (Зависимость контента) Содержимое этого (будущего) файла будет вставлено в этот шаблон.
- **`about.md` (Категории 1, 2, 3):** (Источник) Определяет JSON-структуры, которые будут вставлены в плейсхолдеры.

## 3\. Описание и Нюансы Реализации

### 3.1. Создание Файла

Разработчик (Prompt Engineer) должен создать файл по следующему пути:

- `src/prompts/v1/user_template.md`

### 3.2. Содержание Файла `user_template.md`

Файл должен быть написан на **русском языке** и содержать _только_ плейсхолдеры и заголовки разделов (для структурирования). `LLMRequestAssemblerService` будет отвечать за замену плейсхолдеров на `JSON.stringify(...)` соответствующих объектов.

**Содержание (Пример):**

> ## Контекст Стратегии и Риска
>
>     {{STRATEGY_CONTEXT}}
>
> ## Данные Рынка (Triggered Pair: {{TRIGGERED\_PAIR}})
>
>     {{MARKET_DATA_JSON}}
>
> ## Технический Анализ (Triggered Pair: {{TRIGGERED\_PAIR}})
>
>     {{TECHNICAL_ANALYSIS_JSON}}
>
> ## Состояние Портфеля (Global)
>
>     {{ACCOUNT_STATE_JSON}}
>
> ## Требуемая Схема Ответа (JSON Output Schema)
>
> Ты **ОБЯЗАН** вернуть ответ в формате JSON, который **СТРОГО** соответствует этой схеме.
>
>     {{OUTPUT_SCHEMA_MD}}
>
> ## ЗАДАЧА
>
> {{FINAL\_QUESTION}}

### 3.3. Проектирование Плейсхолдера `{{FINAL_QUESTION}}`

Этот плейсхолдер не является статичным. `LLMRequestAssemblerService` (Задача 4.6) будет генерировать его "на лету", используя другой, _внутренний_ шаблон.

- **Нюанс:** Разработчик (Prompt Engineer) должен спроектировать этот финальный вопрос в соответствии с планом (Задача 10.4).
- **Пример текста для `FINAL_QUESTION`:**

  > Триггер сработал для `{{TRIGGERED_PAIR}}`.

  > **Причина вызова:** `{{TRIGGER_REASON}}`. **Текущий макро-контекст:** `{{MACRO_TEXT}}` (Индекс: `{{MACRO_VALUE}}`).

  > Проанализируй `{{TRIGGERED_PAIR}}` (включая `market_data` и `technical_analysis`) в контексте всего портфеля (`account_state`).

  > Действуй в рамках своей роли (из `system prompt`) и `risk_rules` (из `strategy_context`).

  > Сформулируй свой анализ в поле `justification` и верни JSON-ответ.

- **Задача для `LLMRequestAssemblerService` (4.6):** Этот сервис должен будет взять `trigger_reason` (e.g., "Price Trigger Hit"), `macro_context.fear_and_greed_text` (e.g., "Extreme Fear") и вставить их в этот шаблон, чтобы сформировать `FINAL_QUESTION`.

## 4\. Критерии Приемки (Acceptance Criteria)

1.  **\[Файл\]** Файл `src/prompts/v1/user_template.md` создан.
2.  **\[Плейсхолдеры Данных\]** Шаблон содержит плейсхолдеры для JSON-данных: `{{STRATEGY_CONTEXT}}`, `{{MARKET_DATA_JSON}}`, `{{TECHNICAL_ANALYSIS_JSON}}`, `{{ACCOUNT_STATE_JSON}}`.
3.  **\[Плейсхолдер Схемы (Критично)\]** Шаблон содержит плейсхолдер `{{OUTPUT_SCHEMA_MD}}` для внедрения схемы ответа (из Задачи 10.5).
4.  **\[Плейсхолдер Задачи\]** Шаблон содержит финальный плейсхолдер `{{FINAL_QUESTION}}`.
5.  **\[Проектирование Задачи\]** Определен текст для `{{FINAL_QUESTION}}` и его собственные плейсхолдеры (`{{TRIGGERED_PAIR}}`, `{{TRIGGER_REASON}}`, `{{MACRO_TEXT}}` и т.д.).
